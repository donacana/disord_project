# 연예·문화 Backend 답변 품질 개선 보고서

2026-09-10 실제 DB와 설정된 OpenAI 서비스로 실행한 결과입니다. 실제 검증은 `rag.answer_question()`을 직접 호출했으며, 아래 실측에는 mock을 사용하지 않았습니다. 별도의 회귀 테스트 57개도 통과했습니다.

## [실패 원인]

1. **A: 질문 이해 실패** — 수정 전 실제 `요즘 어떤 아이돌이 유명해?`는 `intent=trend`, `confidence=0.8`로 해석되어 일반 RAG로 이동했고 확인 불가로 끝났습니다. `target_type` 필드와 순위 질문 예시가 없었습니다.
2. **C/D: 후보 추출·분류 오류** — 기사 1,000건은 조회됐지만 제목 토큰 추출이 언론사명 `위클리오늘`, 일반 단어 `신고`, 작품명 `아리랑`까지 인물 후보로 만들었습니다. 이름을 찾은 뒤 본문 전체를 문자열 검색하는 방식 역시 가수 이름 `이제`와 일반 단어를 혼동했습니다. 이제는 기사별로 실제 인물을 지칭한다고 추출된 언급만 계산합니다.
3. **집계 출처 오류** — DB의 `source_name=네이버뉴스`는 여러 언론사를 포함했습니다. 트렌드의 서로 다른 출처 수를 기사 URL 도메인 기준으로 바꿨습니다.
4. **생성 정보 부족** — 트렌드 생성 모델은 이름·수치만 받고 최대 3문장으로 제한되어 있었습니다. 대표 기사 본문과 명시적인 순위 대상 목록이 없었습니다.
5. **E: 검증 단계 손실** — 각 인용 기사 하나하나에 문장의 모든 단어가 있어야 한다는 조건이 통합 설명을 제거했습니다. 문단 끝에만 붙은 인용 때문에 앞 문장들도 삭제됐습니다. 의미 검증 결과를 문장별 JSON으로 받고 인용을 각 문장에 배정하도록 수정했습니다.

## [Answer Generation 변경]

- 질문에 직접 답하는 첫 결론, 대상별 기사 언급량·출처 수와 대표 기사 설명, 조회 기간·집계 범위를 유지합니다.
- 순위 대상 목록과 각 대상의 실제 근거 번호를 별도로 전달합니다. 대표 기사에 나오는 다른 이름을 새로운 순위 대상으로 사용하지 않도록 지시합니다.
- 일반 RAG도 여러 기사의 활동·성과를 통합합니다. 실제 스트레이 키즈 질문은 여러 출처를 인용한 5문장을 반환했습니다.
- 후보가 1개라도 있으면 답하며 생성·검증 실패 시 실제 집계 값과 기사 제목으로 부분 답변합니다. 인기나 긍정적인 활동량으로 집계 의미를 바꾸지 않습니다.

## [Validator 변경 여부]

변경했습니다. 의미 검증이 각 문장의 주체·행위·시점·부정과 인용을 확인한 뒤 `text/citations/section` 배열을 반환합니다. 검증된 통합 문장에는 각 원문의 모든 단어가 같아야 한다는 조건을 다시 적용하지 않습니다. 로컬에서는 잘못된 인용, 없는 수치·단위와 따옴표로 표시된 고유명사 등을 계속 검사합니다. 지원되는 문장은 유지하며 unsupported 문장만 삭제합니다.

의미 검증 장애나 전부 거절된 초안을 단순 단어 겹침으로 복원하지 않습니다. 직접 관련된 원문 문장·제목 또는 결정적으로 계산한 집계 사실만 복구합니다. 최종 출처 번호는 사용된 실제 기사에 맞춰 재배정하므로 validated_answer와 final_answer의 인용 번호가 달라질 수 있습니다.
